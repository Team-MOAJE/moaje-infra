# Demo Studio 사용 안내

접속: http://localhost:8090 (test-tools 프로필). 외부 공개용 서비스가 아닙니다.

## 준비와 생성

1. Docker Desktop과 apps 프로필을 실행합니다.
2. `docker compose --profile apps --profile test-tools up -d --build test-fixture-console mock-banking`으로 도구를 실행합니다. 이 PC에서는 DB 외부 포트 환경변수 13307/13308/13309를 유지합니다.
3. 소비 유형, 은행, 이번 달 포함 1~6개월, 월 8·40·80건, 개설 잔액을 선택합니다.
4. 생성 버튼을 한 번 누르고 완료를 기다립니다. 기본값은 3개월 소비 거래 120건입니다.
5. 생성 이력에 표시되는 테스트 휴대폰 번호와 PIN으로 앱에 로그인합니다.
6. 계좌 상세, 거래내역 스크롤, 월별·카테고리 집계를 시연합니다.

신규 사용자는 회원가입만 합니다. 잔액 0원 사용자는 활성 계좌를 개설하되 소비 거래를 생성하지 않습니다.
일반 페르소나는 8개 가맹점 소비 항목을 반복합니다. 현재 생성기는 별도 수입·송금을 만들지 않으므로 해당 집계는 0원일 수 있습니다. 개설 잔액은 정기 수입이 아닙니다. Work 온보딩·시뮬레이션 데이터도 자동 생성하지 않습니다.

## 처리 경로와 확인 범위

콘솔 → Gateway 회원가입·로그인 → Banking 계좌 개설 → Mock 테스트 거래 생성 → Asset refresh → 월별/카테고리 GET → 거래내역 전체 페이지 확인.

- Mock의 월별 거래량만 확장했습니다. Banking·Asset DB에 직접 데이터를 삽입하지 않습니다.
- 작업은 한 번에 하나씩 수행하고, 결과는 `fixture-console-data` 볼륨에 보존합니다. JWT는 저장하지 않습니다. 합성 테스트 로그인 정보는 저장됩니다.
- 브라우저를 닫아도 작업은 계속됩니다. 콘솔 재시작으로 끊긴 작업은 실패로 표시하며 자동 생성 재시도하지 않습니다.
- 실패 시 이미 생성된 회원·계좌가 남을 수 있습니다. 새 생성 버튼으로 복구를 시도하면 또 다른 사용자가 생성됩니다.
- 계좌 갱신·집계 조회는 refresh 후 저장 집계를 읽습니다. 없을 때만 기존 Asset GET 로직이 최초 집계·Outbox를 생성합니다. 강제 재집계나 Kafka 소비 완료 확인 기능이 아닙니다.
- 페이지별 건수는 실제 거래내역 API를 순회한 결과입니다. 중복 ID나 생성 건수보다 적은 내역은 성공으로 표시하지 않습니다.
- 기본 테스트 PIN은 로컬 합성 계정에서만 사용합니다. 콘솔은 localhost 바인딩과 동일 출처 JSON 요청 검사를 유지합니다.

## 버튼 초기화

1. http://localhost:8090 → **전체 초기화** 메뉴로 이동합니다.
2. 삭제 범위를 읽고 확인 체크를 선택합니다.
3. `전체 초기화`를 입력하고 **전체 데이터 삭제 후 재시작**을 누릅니다.
4. 페이지에 단계별 진행 상태가 표시됩니다. 완료 후 앱에서 로그아웃하고 다시 가입합니다.

삭제 범위: 같은 Compose 프로젝트의 Auth·Banking·Asset·Work 업무 테이블 전체, 공유 Redis의 캐시·세션, Infra Mock Redis 원장, Kafka 업무 토픽 메시지, 콘솔 생성 이력. 기본적으로 별도 `moaje-mock-banking` 프로젝트의 두 컨테이너도 찾아 Mock Redis 원장을 비웁니다. 별도 프로젝트 이름은 `RESET_EXTRA_MOCK_PROJECT`로 설정합니다. 해당 프로젝트가 없으면 건너뛰고, 예상과 다른 서비스 구성이면 거절합니다.

DB 스키마와 `flyway_schema_history`, `alembic_version`은 유지합니다. 테이블을 비우므로 Work의 기본 업무 데이터도 지워집니다. Docker 볼륨·이미지·인증서와 모니터링 데이터는 삭제하지 않습니다. 브라우저/앱 안에 저장된 토큰은 직접 제거할 수 없으므로 앱에서 로그아웃해야 합니다.

실행 순서: API·Worker 중지 → Kafka 파티션 끝까지 메시지 제거 및 시작 offset 검증 → MySQL 업무 행 삭제와 0건 검증 → Redis FLUSHALL SYNC → 원래 실행 중이던 서버 재시작 → Gateway 경유 HTTP 기동 확인 → 콘솔 이력 삭제.

실패 시 일부 데이터만 삭제됐을 수 있습니다. 삭제 단계에서 실패하면 서버를 자동 재시작하지 않습니다. 원인을 해결하고 동일 버튼으로 재시도합니다. 초기화가 진행 중이거나 실패 상태이면 페르소나 생성·갱신을 차단합니다. 재시작 중 실패한 경우에는 일부 서버가 켜져 있을 수 있습니다.

설치 폴더 경로는 사용하지 않습니다. `reset-agent`가 자신의 Compose 프로젝트 라벨로 컨테이너를 찾습니다. Linux 컨테이너를 사용하는 Docker Desktop과 Docker Engine을 대상으로 합니다. 원격/공용 운영 환경에는 사용하지 않습니다.

### 권한과 접근 경계

사용자 승인에 따라 **로컬 테스트 전용 reset-agent에만 Docker 소켓을 마운트**합니다. 이 소켓 권한 자체는 Docker 전체를 제어할 수 있으므로, 지정 서비스 제한은 코드상의 방어이며 Docker 권한을 격리한 샌드박스가 아닙니다. 에이전트에는 호스트 공개 포트가 없고 임의 명령/컨테이너 지정 API도 없습니다. 콘솔은 localhost에만 공개하고 동일 출처 검사·임시 확인 토큰·확인 문구를 모두 요구합니다. 에이전트와 콘솔 사이에는 공유 토큰을 사용합니다. `test-tools` 프로필에서만 실행합니다.

기존 셸 초기화 스크립트는 볼륨까지 지우는 별도 방식입니다. 버튼 초기화와 범위가 다르므로 혼동하지 않습니다.

## 검증

- 콘솔 단위 테스트: `docker run --rm -e FIXTURE_ADMIN_TOKEN=test -v "<콘솔 경로>:/app:ro" -w /app python:3.12-slim python -B -m unittest -v test_app`
- Mock 테스트: `gradlew.bat test --tests com.example.bankingmockup.fixture.application.TestFixtureServiceTest`
- 실제 생성과 화면 확인 결과는 작업 완료 보고에 따릅니다.

### 2026-11-08 실제 로컬 검증

- 콘솔 단위 테스트 7개, Mock FixtureService 테스트 4개 통과.
- 균형 소비 3개월 × 40건: 생성 120건, Asset 조회 120건, 페이지 50/50/20건, SYNCED.
- 초기 5,000,000원 - 소비 2,302,500원 = 잔액 2,697,500원 일치. 각 월 지출 767,500원.
- 계좌 갱신 재실행 후 거래 수 120건·집계 revision 1 유지.
- 잔액 0원 시나리오: 잔액 0원·거래 0건·월별 0원 집계 조회 성공.
- 신규 사용자 시나리오: 회원가입·로그인 성공, 계좌 생성 없음.
- 콘솔 컨테이너 재시작 후 세 시나리오의 실행 이력과 결과 보존 확인.
- 외부 Origin으로 보낸 생성 요청은 403으로 차단.
- 검증 중 생성한 합성 계정은 생성 이력에 남겨 시연에 재사용합니다. 기존 계정·볼륨은 삭제하지 않았습니다.
- 현재 시연 환경의 전체 초기화는 실행하지 않았습니다.

### 버튼 초기화 검증

- 기존 콘솔 7개 + reset-agent 5개 단위 테스트 통과.
- 별도 `moaje-reset-verification` 저장소에서 실측: 외래키가 있는 업무 테이블 0건, Flyway·Alembic 이력 유지, Redis 0건, Kafka 2개 파티션 시작/끝 offset 일치, 반복 삭제 성공.
- 확인 토큰 없는 초기화 요청은 HTTP 400, 상태는 IDLE 유지.
- 실제 Infra 대상 목록에 내부 Mock 및 별도 Mock이 모두 포함됨을 읽기 전용 확인.
- 현재 사용자 데이터와 세 페르소나는 보존. 임시 검증용 컨테이너만 정리함.
